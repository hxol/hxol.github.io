# OpenWRT 划分 VLAN 与网络隔离配置指南

本文档适用于拥有独立 WAN 口与单一 LAN 口的 OpenWrt（24.10 及以上版本）路由器。核心思路是将唯一的 LAN 口配置为 **Trunk（干道）**，通过“**二层网桥 VLAN 过滤**”配合“**三层防火墙区域**”，实现下联设备的网段隔离与按需互通。

## 网络架构与网段规划

*   **WAN 接口**：独立运作，负责拨号或获取上游公网 IP。
*   **LAN 接口**：作为干道连接至带 VLAN 功能的交换机，复用承载以下所有网段流量：

| VLAN ID | 网段规划 | 用途说明 |
| :--- | :--- | :--- |
| **1** | `192.168.253.253/24` | **默认管理**：承载核心网络设备的管理后台流量 |
| **20** | `192.168.20.1/24` | **高危接入**：无安全保障的未知设备、访客设备 |
| **30** | `192.168.30.1/24` | **日常无线**：家人日常使用的 WiFi 设备 |
| **40** | `192.168.40.1/24` | **安防监控**：NVR 录像机与 IPC 摄像头 |
| **50** | `192.168.50.1/24` | **智能家居**：IoT 物联网传感器、智能家电 |
| **60** | `192.168.60.1/24` | **安全内网**：高频访问的 NAS、主干生产力电脑 |

> **架构目标**：所有 VLAN 均可访问互联网；VLAN 之间默认强制隔离；可通过防火墙规则实现跨网段的单向访问（如：安全内网单向控制 IoT 设备）。

---

## 防失联预案与风险提示

配置底层二层网络时，极易因网桥重启导致与路由器断开连接。
*   **备用通道**：若条件允许，在配置期间可暂时通过无线 WiFi 连接路由器后台；或开启 WAN 口的临时后台访问权限（配置完成后关闭），以防 LAN 口配置失误导致“变砖”。
*   **端口匹配原则**：路由器的 LAN 口为 Trunk；下联交换机接路由器的口也必须为 Trunk，接普通终端的口为 Access。

## 阶段一：二层网桥配置 (VLAN 过滤)

OpenWrt 24.10 已全面采用 DSA 架构，VLAN 配置直接在虚拟网桥（Bridge）上完成，摒弃了旧版“交换机 (Switch)”菜单。

导航至 **网络 (Network) -> 接口 (Interfaces) -> 设备 (Devices)**：

*   找到默认网桥设备（通常命名为 `br-lan`），点击**配置 (Configure)**。
*   切换至 **网桥 VLAN 过滤 (Bridge VLAN filtering)** 标签，勾选 **启用 VLAN 过滤**。
*   根据下表添加 VLAN 映射。请注意识别您的 LAN 物理网口名称（如 `eth1`、`lan` 或 `eth0`），并确保 `Local`（代表路由器 CPU）的标签状态正确，以便路由器能处理该 VLAN 的数据。

| VLAN ID | LAN 物理网口状态 | 本地 CPU (`Local`) | 说明 |
| :--- | :--- | :--- | :--- |
| **1** | 未打标签 (Untagged) | 未打标签 (Untagged) | 默认主 VLAN，保持不打标以兼容传统设备 |
| **20** | 已打标签 (Tagged) | 已打标签 (Tagged) | 剥离出高危设备流量 |
| **30** | 已打标签 (Tagged) | 已打标签 (Tagged) | 剥离出无线网络流量 |
| **40** | 已打标签 (Tagged) | 已打标签 (Tagged) | 剥离出监控网络流量 |
| **50** | 已打标签 (Tagged) | 已打标签 (Tagged) | 剥离出智能家居流量 |
| **60** | 已打标签 (Tagged) | 已打标签 (Tagged) | 剥离出安全内网流量 |

*注：若需新增 VLAN，只需在此表中添加新行，均设为 Tagged 即可，具备极强的可扩展性。*
确认无误后点击保存。

## 阶段二：三层逻辑接口与 DHCP 配置

底层通道打通后，需为每个 VLAN 建立“虚拟网卡”并分配网关 IP。

导航至 **网络 (Network) -> 接口 (Interfaces)**：

*   **配置默认管理网段 (VLAN 1)**：
    *   编辑现有的 `lan` 接口。
    *   设备绑定为 `br-lan.1`（或保持 `br-lan`）。
    *   IPv4 地址设为 `192.168.253.253`，子网掩码 `255.255.255.0`。
*   **批量添加独立 VLAN 接口**（以新增 VLAN 20 为例，其他以此类推）：
    *   点击 **添加新接口**，名称设为 `LAN_20`。
    *   协议选择 **静态地址 (Static address)**。
    *   **设备 (Device)** 务必选择对应的逻辑网桥口，即 `br-lan.20`。
    *   设置 IPv4 地址为该网段的网关（如 `192.168.20.1`），掩码 `255.255.255.0`。
    *   在接口下方找到 DHCP 服务器模块，点击**设置 DHCP 服务**以启用动态 IP 分配。
*   **重复上述操作**：将 VLAN 30、40、50、60 的接口全部建立完毕。

## 阶段三：防火墙安全与流量隔离

为实现“防内网爆破”、“强制隔离”和“正常上网”，推荐采用**默认白名单机制**，而非原先的黑名单机制。

导航至 **网络 (Network) -> 防火墙 (Firewall) -> 区域 (Zones)**：

### 核心区域建立
为每一个需要隔离的接口（或安全级别相同的多个接口）建立对应的防火墙区域。以 `zone_v20`（绑定 `LAN_20` 接口）为例，采用以下高安全标准配置：

*   **输入 (Input)**：**拒绝 (Reject)** 
    *   *作用：彻底封死该网段设备对路由器本身的访问（如 Web 后台 80/443、SSH 22 等端口）。*
*   **输出 (Output)**：**接受 (Accept)**
    *   *作用：允许路由器主动发包给该网段设备。*
*   **转发 (Forward)**：**拒绝 (Reject)**
    *   *作用：切断该网段与其他内网 VLAN 之间的横向数据穿透，实现物理级隔离。*
*   **允许转发到目标区域 (Forward to)**：**仅勾选 `wan`**
    *   *作用：赋予该网段设备访问公共互联网的权限。*

### 核心服务放行 (DNS 与 DHCP)
由于前一步将 Input 设为了 Reject，设备会无法获取 IP 和解析域名。必须通过通信规则精准放行基础服务：
*   切换至 **防火墙 -> 流量规则 (Traffic Rules)**，新建规则：
    *   名称：`Allow_DNS_DHCP`
    *   源区域：勾选所有受限的 VLAN 区域（如 `zone_v20`、`zone_v30` 等）
    *   目标区域：**设备 (Device/Input)**
    *   协议：**TCP/UDP**
    *   目标端口：**`53` (DNS), `67` (DHCP)**
    *   动作：**接受 (Accept)**

### 跨网段单向访问设定 (进阶/可选)
若需用安全内网（VLAN 60）去管理其他隔离网段，可按需修改 `zone_v60` 区域的转发规则：
*   在 `zone_v60` 的 **允许转发到目标区域 (Forward to)** 中，除了 `wan`，额外勾选 `zone_v40` (监控) 或 `zone_v50` (IoT)。
*   *效果达成：VLAN 60 内的设备可主动访问摄像头或智能家居，但反向请求会被防火墙拦截，保障主内网安全。*

## 阶段四：下联交换机配置对照

交换机的配置逻辑需与路由器形成完美的镜像映射。假设交换机端口 1 连接路由器的 LAN 口：

*   **端口 1 (上联路由器接口)**：配置为 **Trunk** 模式。
    *   VLAN 1：设为 Untagged（与路由器保持一致，用于管理交换机自身）。
    *   VLAN 20/30/40/50/60：全部设为 **Tagged**，允许带有标签的数据通过。
*   **硬连线终端接口 (如端口 4 接 NVR 录像机)**：配置为 **Access** 模式。
    *   PVID 设为 40。
    *   VLAN 40 设为 Untagged（仅允许 VLAN 40 进出）。
*   **无线 AP 接口 (如端口 3 接全屋 WiFi 节点)**：
    *   *若 AP 支持 VLAN 功能*：端口配置为 **Trunk** 模式，VLAN 1 Untagged（AP 管理），VLAN 30、VLAN 50 设为 Tagged 透传。在 AP 管理后台将不同 SSID 绑定至对应的 VLAN ID。
    *   *若为普通家用路由器改 AP*：端口配置为 **Access** 模式，PVID 设为对应的单一业务（如 VLAN 30），使连接该无线的所有设备强制落入 VLAN 30。

## 验证测试与网络优化

*   **连通性与隔离性双测**：
    将测试电脑接入分配给 VLAN 20 的交换机端口：
    *   检查 IP 分配：应自动获取到 `192.168.20.x`。
    *   外网测试：`ping 223.5.5.5` 应正常连通。
    *   隔离测试：`ping 192.168.60.1`（安全内网）应请求超时。
    *   防越权测试：浏览器访问 `http://192.168.20.1`，应无法打开路由器管理页面。
*   **智能家居跨网段发现 (mDNS/Bonjour 转发)**：
    由于二层广播被隔离，手机在 VLAN 60 内可能无法搜到 VLAN 50 内的投屏或智能家电。
    *   **解决方案**：在 OpenWrt 中安装 `avahi-daemon` 或 `omcproxy`（组播路由守护进程）。
    *   在插件中启用 **反射 (Reflection)** 功能，并勾选需互通的逻辑接口（如 `LAN_60` 与 `LAN_50`），即可实现跨 VLAN 的设备自动发现。
