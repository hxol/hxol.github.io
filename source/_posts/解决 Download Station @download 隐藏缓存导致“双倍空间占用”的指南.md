# 解决 Download Station @download 隐藏缓存导致“双倍空间占用”的指南

在群晖 NAS 中，`@download` 文件夹是 **Download Station** 的隐藏缓存目录（通常位于您设置的“临时文件位置”，如 `/volume1/@download`）。

**为什么会占用双倍空间？**
当您的“临时缓存目录”和“最终下载目录”**不在同一个存储卷（Volume）**时，系统无法使用“硬链接（Hard Link）”技术。下载完成后，系统会将文件从缓存**复制**到最终目录。此时：
* 一份文件在最终文件夹（供您查看和使用）。
* 一份文件留在 `@download` 缓存目录中（供 Download Station 继续做种上传）。
此时，文件实际占用了双倍的硬盘空间。即使您在最终文件夹删除了该文件，只要 Download Station 中的任务还在，缓存就不会被释放。

以下是几种**安全清理双倍空间**的方法，按推荐程度从高到低排列：

---

### 方法一：最安全推荐 —— 在 Download Station 中标准移除（不破坏系统逻辑）
这是官方推荐的处理方式，能让系统自动回收空间。

1. **移除任务**：打开 Download Station，找到已完成的下载任务。如果您**不再需要为该任务做种（上传）**，请选中任务，点击**移除**（或右键选择移除），并确认。
2. **清理缓存**：系统在移除任务时，会自动尝试删除 `@download` 中对应的缓存文件。
3. **重启套件**：为了确保空间被彻底释放，建议重启一次套件。
   * 进入 **套件中心** → **已安装** → 找到 **Download Station**。
   * 点击下拉菜单选择 **停用**，等待停用完成后，再点击 **启动**。
4. **检查空间**：稍等几分钟后，查看存储空间是否已恢复。

> **⚠️ 注意**：如果您是 PT（Private Tracker）玩家，需要长期做种，请直接跳至文末的“**终极预防方案**”。

---

### 方法二：进阶操作 —— 通过 SSH 手动清理缓存（适用于异常残留）
有时即便移除了任务，缓存由于权限或系统 Bug 依然未能删除。此时可以通过 SSH 手动清理。

> **🛡️ 安全与隐私警告**：
> 1. SSH 操作拥有最高系统权限，敲击命令需格外谨慎，尤其是 `rm -rf` 命令，**拼写错误可能导致整个系统数据丢失**！
> 2. 操作完毕后，请务必关闭 SSH 服务，防止因暴露默认端口（22）受到黑客爆破攻击。

**操作步骤：**
1. **开启 SSH**：在 DSM 控制面板 → 终端机和 SNMP → 勾选 **启动 SSH 功能**（建议将默认端口 22 改为其他数字，如 2222）。
2. **连接 NAS**：使用终端工具（如 Windows 的 PuTTY / FinalShell，或 Mac 的 Terminal），通过局域网 IP 以管理员账号登录。
3. **切换为 Root 权限**：输入命令 `sudo -i`，再次输入管理员密码。
4. **进入缓存目录**（请将 `volume1` 替换为您实际的临时存储卷）：
   ```bash
   cd /volume1/@download
   ```
5. **查找占用过大的文件夹**：
   ```bash
   du -sh *
   ```
   *您会看到一堆以数字命名的文件夹（这就是任务的专属缓存 ID）。*
6. **删除不需要的缓存**：
   * **情况 A：直接删除废弃任务**：如果您确定某个数字文件夹（如 `12345`）对应的任务已不需要，可直接删除整个文件夹：
     ```bash
     rm -rf /volume1/@download/12345
     ```
   * **情况 B：保留任务记录（技术纠错）**：网上有流传“只删除数据文件，保留 `.torrent` 和 `.resume` 就能继续做种”。**这是一个误区**。如果数据文件被删，Download Station 会报错，无法实际上传数据。但这种操作确实可以让任务继续“显示”在列表中（适合强迫症保留历史记录）。若要如此操作，进入该子文件夹后，仅使用 `rm` 命令删除视频/压缩包等大文件即可。
7. **收尾**：操作完成后，输入 `exit` 退出 SSH。回到控制面板**关闭 SSH 功能**。重启 Download Station 套件以刷新缓存状态。

> **💡 新手福利**：如果您害怕命令行，可以使用 **WinSCP** 软件。使用 SCP 协议以 Root 权限登录 NAS，即可像使用 Windows 资源管理器一样，可视化浏览、删除 `@download` 里的隐藏文件。

---

### 方法三：核弹级清理 —— 卸载重装套件（会清空所有下载历史）
如果您积攒了几个 TB 的僵尸缓存，且不想折腾 SSH，这是最简单的“彻底大扫除”方式。

1. **备份（可选）**：如果有一些重要的未完成任务，请先尝试导出/记录。
2. **卸载套件**：前往 **套件中心** → **Download Station** → 点击 **卸载**。
3. **⚠️ 关键步骤**：在弹出的确认窗口中，**务必勾选“删除上面列出的项目”（Delete all items/settings）**。这一步会强制清除所有临时文件和缓存目录。
4. **重新安装**：卸载完成后，重新在套件中心安装 Download Station 即可。此时您的 `@download` 文件夹已被彻底清空。

---

### 🌟 终极预防方案：如何永远避免双倍空间占用？

清理只是治标，合理的设置才能治本。强烈建议您按以下原则设置 NAS：

1. **同卷（Same Volume）原则**：
   将 Download Station 的**“临时文件位置”**和**“下载完成的最终保存位置”**设置在**同一个存储卷**（例如都在 Volume 1）。
   * **原理解析**：同卷状态下，群晖会使用“硬链接（Hard Link）”。缓存目录和最终目录指向硬盘上的同一个物理文件。此时不管文件有多大，**永远只占用一份空间**，并且可以完美做种！
2. **设置自动停止做种**：
   如果您不玩 PT，不需要长期保种，请在 Download Station 的设置中，将 **BT/PT 设置**里的“自动停止做种”条件设置为：**分享率达到 100%** 或 **做种时间达到 24 小时**。任务完成后自动停止，方便您随时清理。
3. **善用存储分析器**：
   安装群晖官方套件 **存储分析器（Storage Analyzer）**，定期生成报告，重点关注 `@download` 和 `#recycle`（回收站）的体积异常，做到心中有数。
