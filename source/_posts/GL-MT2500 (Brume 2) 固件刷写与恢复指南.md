# GL-MT2500 (Brume 2) 固件刷写与恢复指南

本文基于 GL.iNet 官方文档与 OpenWrt 社区最新经验整理。内容涵盖从第三方固件刷入、官方固件回退到底层 U-Boot 救砖的完整流程，以及刷机过程中的风险防控。

## 核心要点速览
* **刷机原则**：跨版本或跨分支（如官方与原生 OpenWrt 之间互相切换）刷机时，**务必取消保留配置**，以免引发内核冲突或服务异常。
* **文件格式**：Sysupgrade 升级通常使用 `.bin` 后缀固件。
* **终极兜底**：设备变砖无需恐慌，GL-MT2500 自带 U-Boot Fail-Safe Web 界面，可通过底层强刷恢复。

---

## 刷入原生 OpenWrt 或自编译固件

### 前期准备
* **固件获取**：使用 OpenWrt 官方或 ImageBuilder 编译针对 `mediatek/filogic` 平台的 Sysupgrade 镜像。文件命名通常类似于 `openwrt-mediatek-filogic-glinet_gl-mt2500-squashfs-sysupgrade.bin`。
* **环境核对**：检查固件大小是否在 eMMC 存储容量支持范围内，并计算校验和（SHA256/MD5）以确保文件下载完整。
* **网络连接**：PC 需通过网线直连路由器的 LAN 口。

### 方式一：Web 界面常规升级（推荐）
* **访问后台**：浏览器登录当前路由器的 Web 管理后台（GL.iNet 官方固件默认地址为 `http://192.168.8.1`）。
* **上传固件**：进入 **系统** -> **升级固件** -> **本地升级** 页面，将备好的 `.bin` 固件拖入或选中上传。
* **环境隔离**：在最后确认升级时，**取消勾选** “保留设置 (Keep settings)” 选项。
* **完成升级**：点击提交，等待数分钟设备自动重启，路由即可进入全新的系统。

### 方式二：终端 SSH 命令行升级
* **上传固件至设备**：连接网络后，通过 SCP 或直接在终端中使用 `wget` / `curl` 将固件下载至路由器的 `/tmp` 目录（该目录基于 RAM，重启即清空，非常适合存放临时固件）。
* **执行刷写命令**：连接 SSH 后，使用 `sysupgrade` 命令执行刷机，强制不保留配置（使用 `-n` 参数）：
  ```bash
  sysupgrade -n -v /tmp/openwrt-mt2500-<版本号>-sysupgrade.bin
  ```
  *补充提示*：若提示校验失败但确认固件来源绝对可靠，可增加 `-f` 参数强制刷入，但需谨慎。

## 刷回 GL.iNet 官方固件

回退官方系统的逻辑与刷入第三方固件基本一致，重点在于获取纯净的官方镜像并切断旧配置。

* **获取官方固件**：前往 GL.iNet 固件下载中心，下载对应 MT2500 的 Release 或稳定版固件（`.bin` 格式）。
* **通过 LuCI 界面刷回**：如果在原生 OpenWrt 界面下，导航至 **System** -> **Backup / Flash Firmware**，上传官方镜像文件。同样**切记取消勾选** “Keep settings” 或 “保留当前配置”。
* **通过 SSH 刷回**：若在纯命令行环境下，将官方固件放入 `/tmp` 后，执行包含 `-n` 参数的 `sysupgrade` 命令完成降级或回退。

## 救砖与底层修复：U-Boot 恢复模式

当系统彻底崩溃、无法分配 IP 或 Web/SSH 均无响应时，可通过设备内置的 U-Boot 模式进行底层恢复。

### 触发 U-Boot 模式
* **断电与按键**：拔掉路由器电源。按住设备侧面的 **Reset 按钮** 不放。
* **通电并观察**：在按住 Reset 的同时插上电源 。持续按住（大于 5 秒），观察设备 LED 指示灯的闪烁频率（通常为蓝色指示灯快闪数次后变为常亮）。
* **松开按键**：指示灯状态稳定后，即可松开 Reset 按钮，此时设备已成功停留在 U-Boot 引导状态。

### 通过 U-Boot Web 界面刷机
* **配置本机 IP**：将 PC 的以太网卡静态 IP 手动设置为 `192.168.1.2`（子网掩码 `255.255.255.0`），网关留空。
* **进入控制台**：浏览器访问 `http://192.168.1.1`，进入 U-Boot Web 界面。
* **执行刷入**：在页面中选择官方 `.bin` 固件或纯净的第三方镜像，点击上传与更新。页面会有进度提示，完成后设备将自动重启。
* **⚠️ 避坑指南（重要纠正）**：普通救砖**只需上传系统固件**即可。除非 GL.iNet 官方明确要求你修复引导加载程序缺陷，否则**绝对不要**在此界面随意刷入 `fip-mt2500.bin` (Bootloader 镜像) 。刷坏 Bootloader 会导致硬件成为“真砖”，只能通过拆机线刷解决 。

## 风险规避与日常维护建议

通过列表化管理安全事项，便于后续随时排查或补充新发现的踩坑点：

* **校验与匹配**
  * 刷机前务必核对文件名中的硬件代号与平台。例如 GL-MT2500 若误刷成其他类似处理器变种镜像，可能导致网络接口（WAN/LAN PHY 驱动）失效。
* **供电与连接稳固**
  * 刷机期间（尤其是在擦写 eMMC 时）断电极易损坏分区。请使用稳定可靠的电源适配器，并确保网线连接稳固，严禁使用 Wi-Fi 执行跨系统刷机操作。
* **优雅的配置备份策略**
  * 大版本升级或系统替换必定会擦除应用层文件系统及自建服务数据。建议平时刻意分离“系统级配置”和“业务级数据”。
  * 升级前可使用 `scp` 导出 `/etc/config` 核心文件，或通过 `opkg list-installed` 保存已安装的插件列表。在新系统中重新安装插件后按需复原配置，这比盲目“保留所有配置”系统更稳定。
