# 记一次视频无法播放的排查过程

一个视频文件却无法使用任何播放器播放。经过一番排查，发现它本质上是一个被伪装/重命名的 `rar` 压缩文件。将其后缀名改为 `.rar` 并解压后，里面的视频终于可以正常播放了。

记录一下文件头排查思路以及 `xxd` 命令的常用方法。

## 为什么 xxd 能排查出文件真实格式？

在计算机中，文件的扩展名（如 `.mp4`, `.dat`）只是给用户看的一个标识，文件真正的格式取决于其内部的二进制数据。几乎所有标准的文件格式，在其二进制数据的开头都有几个特定的字节，被称为**文件魔数（Magic Number）**或文件头标志。

例如：
* **RAR 压缩包**：通常以 `52 61 72 21 1A 07` 开头（对应 ASCII 码的 `Rar!...`）。
* **MP4 视频**：通常在开头位置包含 `66 74 79 70`（对应 ASCII 码的 `ftyp`）。
* **ZIP 压缩包**：通常以 `50 4B 03 04` 开头（对应 ASCII 码的 `PK..`）。

遇到无法打开的文件时，用 `xxd` 查看其前几十个字节的十六进制内容，往往就能精准定位文件的真实格式。

## xxd 命令详解

`xxd` 是一个非常强大的命令行工具，它可以将给定的文件或标准输入转换为十六进制形式输出，也可以将十六进制数据反向转换回二进制文件。

### 基本语法
```bash
xxd [options] [inputfile [outputfile]]
```
* **inputfile**：输入文件。如果未指定，则默认读取标准输入。
* **outputfile**：输出文件。如果未指定，则默认输出到标准屏幕（终端）。

### 常用参数说明
* `-l length`：**常用！** 只读取并显示指定长度的字节数（排查文件头时经常只看前 128 或 256 字节）。
* `-s offset`：从文件的某个偏移位置开始读取。支持使用负数，表示从文件末尾向前偏移。
* `-r`：**反向操作**。将十六进制数据（Hex dmp）还原为原始的二进制文件。
* `-p`：纯十六进制输出模式。只输出连续的十六进制字符，不显示地址偏移量和右侧的 ASCII 可读字符。
* `-c cols`：自定义每行显示的字节数，默认是 16 个字节。
* `-g bytes`：自定义每组显示的字节数，默认是 2 个字节为一组。
* `-u`：将输出的十六进制字母（a-f）转换为大写（A-F）。
* `-i`：以 C 语言数组的代码格式输出（常用于将小文件硬编码嵌入到 C/C++ 代码中）。
* `-b`：将输出转换为**纯二进制**格式（0和1），而不是十六进制。

## 实用案例

### 1. 排查未知文件格式（查看文件头）
我们只需要查看前 256 个字节，以免终端被大量数据刷屏：
```bash
xxd -l 256 unknown_video.dat
```
*输出示例：*
```text
00000000: 5261 7221 1a07 0100 7300 000d 0000 0000  Rar!....s.......
...
```
*(通过右侧的 `Rar!` 和左侧的 `5261 7221`，一眼就能看出这是一个被改了后缀的 RAR 压缩包。)*

### 2. 生成纯十六进制字符串
如果你只需要提取文件的数据，不需要左侧的地址行号和右侧的 ASCII 文本，可以使用 `-p` 参数：
```bash
xxd -p -l 16 unknown_video.dat
```
*输出结果：*
```text
526172211a0701007300000d00000000
```

### 3. 将图片/小文件转为 C 语言数组
如果你做嵌入式开发，需要把一个小图标直接写死在代码里，这个命令是神器：
```bash
xxd -i icon.png > icon.h
```

### 4. 将十六进制代码还原为文件 (Hex to File)
如果你拿到了一串十六进制的文本（比如保存在 `hex.txt` 中），想要把它还原成真正的文件：
```bash
xxd -r -p hex.txt output_recovered.rar
```

## 总结
遇到格式异常的文件时，不要过度依赖扩展名，利用 `xxd` 看看文件的“基因（文件头）”，往往能快速拨开迷雾，找到解决方案。
