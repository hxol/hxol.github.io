# OpenWrt 进阶指南：使用 Crontab 配置定时重启及自动化任务

在 OpenWrt 路由器中，合理配置定时重启和自动化任务，可以有效释放内存并保持系统稳定。本文档提供了一套标准、可扩展的定时任务配置流程。

### 核心配置流程

**进入编辑界面**
通过 SSH 连接到您的 OpenWrt 路由器后，在命令行输入以下命令以进入当前用户的定时任务编辑面板：
```bash
crontab -e
```
*注：OpenWrt 默认调用 `vi` 编辑器。*

**开启编辑模式**
在英文输入法状态下，按下键盘上的 `i` 键。此时终端底部通常会出现 `I` 或 `Insert` 字样，表示已进入可输入状态。

**写入任务规则**
将光标移动到空白处，添加您需要的定时任务。以“每天凌晨 4:30 定时重启”为例，请粘贴以下内容：
```bash
# 每天 04:30 执行重启
# 延迟 70 秒并更新系统时间标记文件，防止无 RTC 时钟的设备陷入无限重启循环
30 4 * * * sleep 70 && touch /etc/banner && reboot
```

**保存并退出**
编写完成后，按下 `Esc` 键退出编辑模式；接着输入 `:wq` 并按回车键（Enter），即可保存修改并返回主命令行。

**重启服务使配置生效**
定时任务写入后，必须重启 Cron 服务才能加载最新配置。另外，为防止设备断电重启后定时任务失效，建议一并设置服务开机自启：
```bash
/etc/init.d/cron restart
/etc/init.d/cron enable
```

---

### 原理解析：为什么需要 `sleep 70` 和 `touch`？

很多普通路由器主板上**没有硬件时钟电池（RTC）**。这就导致设备每次重启后，系统时间会丢失，OpenWrt 默认会读取 `/etc/banner` 等系统文件的“最后修改时间”来作为开机的初始时间，直到网络时间同步（NTP）成功为止。

如果不加延迟直接触发重启（例如刚好在 `4:30:00` 重启），路由器光速开机后，若 NTP 尚未同步，系统时间可能依然停留在文件记录的 `4:30` 左右。Cron 服务一旦启动，会误以为“现在正是 4:30”，从而**再次触发重启任务，导致设备陷入无限重启的死循环**。

**解决方案的逻辑：**
- `sleep 70`：让任务先暂停 70 秒，跨过 4:30 这个时间点（到达 4:31）。
- `touch /etc/banner`：更新系统文件的时间戳为 4:31。
- `reboot`：执行重启。这样设备开机时的初始时间就是 4:31，完美避开了 4:30 的触发条件。

### 任务扩展库（可按需增删）

本指南具备高扩展性。如果您需要添加其他自动化任务，只需再次运行 `crontab -e`，参考下方模板将对应的代码追加到新行即可。

**基础时间格式参考**
定时任务的前五位分别代表：`分钟` `小时` `日` `月` `星期`。

**常用任务清单**

- **定时关闭/开启 Wi-Fi（例如半夜防沉迷）**
  ```bash
  # 每天 23:30 关闭 Wi-Fi
  30 23 * * * wifi down
  
  # 每天 06:00 重新开启 Wi-Fi
  0 6 * * * wifi up
  ```

- **定时清理系统缓存（释放运行内存）**
  ```bash
  # 每天凌晨 3:00 清理一次页面缓存
  0 3 * * * sync && echo 3 > /proc/sys/vm/drop_caches
  ```

- **定时重新拨号（更新公网 IP，防止运营商强制断线）**
  ```bash
  # 每周三凌晨 4:00 重启 WAN 口 (将 wan 替换为您的实际拨号接口名)
  0 4 * * 3 ifup wan
  ```

### 常见问题排查

- **任务没有按时执行？**
  请在终端输入 `date` 命令，检查当前 OpenWrt 系统的时区和时间是否准确。如果时间不对，请前往“系统 -> 系统属性 -> 时间同步”中配置正确的 NTP 服务器及所属时区（如 `Asia/Shanghai`）。
- **如何查看已配置的任务？**
  使用命令 `crontab -l` 可以在不进入编辑模式的情况下，快速预览当前生效的所有定时任务。
